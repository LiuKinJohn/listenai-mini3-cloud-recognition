# 云端与设备配置

## 阿里云函数

创建华北 2（北京）Node.js 20 函数，入口为 `index.handler`，上传 `relay/index.js`，执行超时至少 60 秒，允许访问公网。测试部署最小实例数为 0；请自行设置用量告警。

设置环境变量：

| 名称 | 内容 |
| --- | --- |
| `BailianApiKey` | 自己的百炼北京区域 API Key，模型代码为 `qwen3.8-flash`；请确认该模型对自己的账号可用。 |
| `DeviceToken` | 随机设备令牌，与设备配对配置对应。 |

创建 HTTP 触发器，仅开放 GET / POST，使用 Bearer 认证，再设置独立的网关令牌。网关会先认证请求；`POST /recognize` 还检查 `X-Device-Token`。图片须为 JPEG，最大 350 KiB。

`GET /health` 不调用模型。`POST /recognize` 不在业务代码主动记录图片、请求正文或密钥；平台日志策略需要自行配置。

## 配对

Windows PowerShell 下可运行 `relay/create-device-token.ps1 -Replacement` 生成设备令牌，运行 `-Gateway` 生成独立网关令牌。脚本将令牌复制到剪贴板并使用当前 Windows 用户的 DPAPI 加密保存；应直接粘贴到控制台相应字段，不要粘贴到聊天或提交至 Git。

确认自己的云函数和网关已保存对应令牌后：

```powershell
.\relay\pair-device.ps1 -Serial 'YOUR_DEVICE_SERIAL'
```

使用 `adb devices -l` 核对目标设备。配对脚本将两枚令牌写入板载 KV，捕获并丢弃包含令牌的命令回显，不写调试日志。设备调试接口仍可读取 KV；本方案没有硬件安全存储。

固件中的主机名目前保留本次测试入口。使用自己的服务时，修改 `overlay/apps/arcs-mini/services/nano_cloud_transport.c` 的 `CLOUD_HOST` 和 `nano_tls_probe.c` 的 `RELAY_HOST`，并检查 CA 信任链。不要把百炼 API Key 写入固件。

## TLS

启用 `CONFIG_MBEDTLS_HAVE_TIME` 与 `CONFIG_MBEDTLS_HAVE_TIME_DATE`。`nano_tls_probe.c` 内的 `ls_time` 及 `mbedtls_platform_gmtime_r` 为 TLS 提供同步后的 UTC 时间；其余配置通过 `src/utils/app-config-tls-generic.h` 接入。移除诊断命令前必须先迁移这两个时间函数。

当前信任锚是 GlobalSign Root CA。原机实测正确域名握手 `result=0, flags=0x0`，错误域名被拒绝 `result=-16, flags=0x4`。运行中要求 Wi-Fi 和有效时间；证书变化可能需要重新配置。

## 本地测试

```powershell
node --test .\relay\test.js
.\relay\test-relay.ps1 -BaseUrl 'https://YOUR-ENDPOINT.cn-beijing.fcapp.run'
```

后者读取本机 DPAPI 文件并只输出状态，不发送照片。只有明确传入 `-ApprovedImage` 才上传指定照片并消耗模型额度。

IP 城市、天气及其他气象背景信息是辅助云型判别、提升识别准确性的预留扩展项，不属于本版未完成项；本版暂不启用。早期 `legacy/cloud-worker` 使用不同的认证及部署方式，当前固件不通过它识云。
